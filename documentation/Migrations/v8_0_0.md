# How to migrate to AdswizzSDK v8.0.0+

Version 8.0.0 of the **_AdswizzSDK_** introduces 2 important changes that require updates to your integration:
- all API interfaces that previously used `Double` or `Long` for time-related parameters have been updated to use Kotlin’s `Duration` type.
- optimized the **_AdswizzSDK_**'s consumer `proguard-rules.pro` to help reduce the final APK size.

This guide will help you upgrade your application to v8.0.0 with minimal effort. The sections below outline the changes introduced in this release. For the complete list of changes, please also refer to the [Changelog](Android/CHANGELOG.md).

## API changed to `Duration` type
### 1. `AdPlayer` interface
Parameter or return types `Double` or `Double?` have been replaced by `Duration` or `Duration?`.

Before v8.0.0:
```kotlin
	 abstract fun getCurrentTime(): Double 
	 abstract fun getDuration(): Double?
	 abstract fun seekTo(position: Double)
```

Since v8.0.0:
```kotlin
	 abstract fun getCurrentTime(): Duration 
	 abstract fun getDuration(): Duration?
	 abstract fun seekTo(position: Duration)
```

### 2. `AdswizzAdRequest` class
Change `Long?` parameter to `Duration?`.

Before v8.0.0:


Since v8.0.0:
```kotlin
	fun withDuration(duration: Duration?) 
```

## `Proguard` rules updates:

Until 8.0.0 version, the **_AdswizzSDK_** used a general `proguard` rule in order to keep its classes that can be accessed through reflection, as follows:
```proguard
-keepclassmembers,allowoptimization public class * {
    public <methods>;
    public <fields>;
}
```
Since 8.0.0 version, this rule was improved to keep only limited range of classes.
> :warning: **Important:** If your project uses `reflection` like `Class.forName("com.your.package.YourClass")` without explicitly declaring your own proguard rules, you may need to update your configuration. Previously, your code may have worked because our broad rule prevented obfuscation, but this is no longer guaranteed with the more specific rules we introduced in 8.0.0.
