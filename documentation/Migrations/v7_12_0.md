# How to migrate to AdswizzSDK v7.12.0+

The v7.12.0 release contains changes regarding how to add **_AdswizzSDK_** player in your project and **_AdswizzAdRequest.Builder_** changes. In this guide you will find everything you need to know on how to update your application with the changes brought by **v7.12.0 and later**. For the latest changes, please visit the [Changelog](Android/CHANGELOG.md).

## What changed in 7.12.0
- `AdswizzAdRequest.Builder` changes: 
  - changed the `withZones(zones: Set<AdswizzAdZone>)` method signature to `withZones(zones: List<AdswizzAdZone>)`.
  - deprecated `.withCompanionZones(companionZones: String?)` method
  - new public method `withCompanionZoneIds(companionZones: List<Int>)`
  - new public method `withCompanionZoneAliases(companionZoneAliases: List<String>)`
- **_AdswizzSDK_**'s InternalPlayer changes:
  - Added new artefact `com.adswizz:exoplayer2x` in the SDK library release.
  - The `com.adswizz:exoplayer-media3` artefact changes.

### AdswizzAdRequest.Builder

#### Ad zones method changes

This change will raise a compilation error that can be easily fixed by replacing the `setOf<AdswizzAdZone>(...)` with `listOf<AdswizzAdZone>(...)` in builder method as follows: 

```kotlin
        AdswizzAdRequest.Builder() //Build the Ad Request with the needed parameters
            .withServer("SERVER_PROVIDED_BY_PIM")
//            .withZones(setOf(AdswizzAdZone("ZONEID_1"), AdswizzAdZone("ZONEID_2"))) <--- removed in 7.12.0
            .withZones(listOf(AdswizzAdZone("ZONEID_1"), AdswizzAdZone("ZONEID_2")))
            .build { adswizzAdRequest ->
//                    handle the request
            }
```
> **Note**
> The order and uniqueness of the provided **_AdswizzAdZone_** array is essential to properly retrieve the ads.

#### Companion zones method changes

The `withCompanionZoneIds(companionZoneIds: List<Int>)` method enables you to provide multiple **numerical** companion zone ids. This is a replacement for legacy `withCompanionZones(companionZones: String?)` method used in previous versions.

```kotlin
        AdswizzAdRequest.Builder() //Build the Ad Request with the needed parameters
            .withServer("SERVER_PROVIDED_BY_PIM")
            .withZones(listOf(AdswizzAdZone("ZONEID_1"), AdswizzAdZone("ZONEID_2")))
//            .withCompanionZones("1243")  <--- deprecated in 7.12.0
            .withCompanionZoneIds(listOf(123, 5678))
            .build { adswizzAdRequest ->
//                    handle the request
            }
```

The `withCompanionZoneAliases(companionZoneAliases: List<String>)` is a convenience method that can be used when companion zones are in a **string** format, as follows:

```kotlin
        AdswizzAdRequest.Builder() //Build the Ad Request with the needed parameters
            .withServer("SERVER_PROVIDED_BY_PIM")
            .withZones(listOf(AdswizzAdZone("ZONEID_1"), AdswizzAdZone("ZONEID_2")))
            .withCompanionZoneAliases(listOf("COMPANION_ALIAS_1", "COMPANION-ALIAS-2"))
            .build { adswizzAdRequest ->
//                    handle the request
            }
```
> **Note**
> Setting simultaneously `companionZoneIds` and `companionZoneAliases` in the AdswizzAdRequest.Builder will throw an Exception.


### **_AdswizzSDK_**'s InternalPlayer changes

Those migration steps applies to integrations that are using **_AdswizzSDK_**'s InternalPlayer only. This section doesn't apply if you are using your own player in order to play the ads content.

> **Note**
> If you are using your player in order to play the ad content, you should add **only** the "com.adswizz:adswizz-sdk:7.12.0" to your `build.gradle`. For more details, please visit [Play ads with your player](Android/SDKAndroid/PlayAdsWithYourPlayerMain.md) section..


#### Exoplayer2 compatibility

This new library provides compatibility across `com.google.android.exoplayer` versions in the range of [2.16.0; 2.19.1]. You can add the new artefact id in your `build.gradle` module as follows:

```groovy

        implementation "com.adswizz:adswizz-sdk:7.12.0" // <--- sdk module
//        implementation "com.adswizz:exoplayer2-19:7.11.1" // <--- old versioned Exoplayer module 
        implementation "com.adswizz:exoplayer2x:7.12.0" // <--- new Exoplayer 
        implementation "com.google.android.exoplayer:exoplayer:$YourExoPlayerVersion" // <--- add your Exoplayer2 dependency version 

```
> **Note**
> The "com.google.android.exoplayer:exoplayer:$YourExoPlayerVersion" dependency must be present in your `build.gradle` in order to successfully use the `com.adswizz:exoplayer2x` wrapper.

#### Android Media3 compatibility

The `com.adswizz:exoplayer-media3` artefact (used on **_AdswizzSDK_**'s InternalPlayer) is now compatible up to `androidx.media3:media3-exoplayer:1.5.1`. The **_AdswizzSDK_** library will not be bundled anymore with `androidx.media3:media3-exoplayer` as transitive dependency, so you should declare dependencies in your `build.gradle` module as follows:

```groovy

        implementation "com.adswizz:adswizz-sdk:7.12.0" // <--- sdk module
        implementation "com.adswizz:exoplayer-media3:7.12.0" // <--- the media3 SDK wrapper
        
        //  add your media3 dependencies
        implementation "androidx.media3:media3-exoplayer:$YourMedia3Version"
        implementation "androidx.media3:media3-exoplayer-dash:$YourMedia3Version"
        implementation "androidx.media3:media3-exoplayer-hls:$YourMedia3Version"
        implementation "androidx.media3:media3-exoplayer-smoothstreaming:$YourMedia3Version"
```

> **Note**
> The following dependencies: "com.google.android.exoplayer:exoplayer", "androidx.media3:media3-exoplayer-dash", "androidx.media3:media3-exoplayer-hls", "androidx.media3:media3-exoplayer-smoothstreaming" must be present in your `build.gradle` in order to successfully use the `com.adswizz:exoplayer-media3` wrapper.
