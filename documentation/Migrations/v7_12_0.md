# How to migrate to AdswizzSDK v7.12.0+

Version 7.12.0 of the **_AdswizzSDK_** introduces 2 important changes that require updates to your integration:
1. A minor breaking change in the `AdswizzAdRequest.Builder` API, along with enhancements to companion zone configuration.
2. A simplified approach for configuring **_AdswizzSDK_**’s InternalPlayer integration in your `build.gradle` file *(only needed when the AdswizzSDK's InternalPlayer handles ad playback)*.

This guide will help you upgrade your application to v7.12.0 with minimal effort. For a full list of changes, please refer to the [Changelog](Android/CHANGELOG.md).


## 1. `AdswizzAdRequest.Builder` API Updates

### Update to the `withZones` method

Because the order of the zones is important and needs to be preserved, we changed the signature of `withZones` method from our `AdswizzAdRequest.Builder`. We decided to use `List` instead of `Set` to ensure that the order is preserved. Of course, this change will raise a compilation error that can be easily fixed by replacing the `setOf<AdswizzAdZone>(...)` with `listOf<AdswizzAdZone>(...)` in builder method as follows: 

```kotlin
AdswizzAdRequest.Builder() //Build the Ad Request with the needed parameters
    .withServer("SERVER_PROVIDED_BY_PIM")
    //.withZones(setOf(AdswizzAdZone("ID_1"), AdswizzAdZone("ID_2"))) // Deprecated as of v7.12.0
    .withZones(listOf(AdswizzAdZone("ID_1"), AdswizzAdZone("ID_2"))) // Updated syntax in v7.12.0
    .build { adswizzAdRequest ->
        //handle the request
    }
```
> **Note**
> The order and uniqueness of the provided  **_AdswizzAdZone_** array are crucial for correctly retrieving ads. While `setOf` maintains insertion order, the `withZones` method accepts a `Set`, whose interface does not guarantee order preservation.

### Companion Zone Enhancements

The new `withCompanionZoneIds(companionZoneIds: List<Int>)` method allows you to specify multiple numeric companion zone IDs. It replaces the deprecated `withCompanionZones(companionZones: String?)` method from previous versions.

```kotlin
AdswizzAdRequest.Builder() //Build the Ad Request with the needed parameters
    .withServer("SERVER_PROVIDED_BY_PIM")
    .withZones(listOf(AdswizzAdZone("ID_1"), AdswizzAdZone("ID_2")))
    //.withCompanionZones("123,5678")  // Deprecated as of v7.12.0
    .withCompanionZoneIds(listOf(123, 5678)) // New method from v7.12.0
    .build { adswizzAdRequest ->
        //handle the request
    }
```

The new `withCompanionZoneAliases(companionZoneAliases: List<String>)` method provides a convenient way to specify companion zones using string aliases instead of numeric IDs. The aliases should be formatted as follows:

```kotlin
AdswizzAdRequest.Builder() //Build the Ad Request with the needed parameters
    .withServer("SERVER_PROVIDED_BY_PIM")
    .withZones(listOf(AdswizzAdZone("ID_1"), AdswizzAdZone("ID_2")))
    .withCompanionZoneAliases(listOf("ALIAS_1", "ALIAS_2")) //convenience method for zone aliases
    .build { adswizzAdRequest ->
        //handle the request
    }
```
> **Note**
> Setting simultaneously `companionZoneIds` and `companionZoneAliases` in the `AdswizzAdRequest.Builder` will throw an Exception.


## 2. How to Update `build.gradle` for **_AdswizzSDK_**'s InternalPlayer

This section is relevant **only** to integrations using the AdswizzSDK’s InternalPlayer. If you’re using your own player to handle ad playback (via the `MediaPlayerState` or `AdPlayer` interfaces), you can safely skip this section.

> **Note**
> If you are using your own player to handle ad playback, you should add **only** the "com.adswizz:adswizz-sdk:7.12.0" to your `build.gradle` file. For more details, please visit [Play ads with your player](Android/SDKAndroid/PlayAdsWithYourPlayerMain.md) section.


### Integrating with `Exoplayer 2.x`

This new SDK version (7.12.0) provides compatibility with `com.google.android.exoplayer` versions from `2.16.0` to `2.19.1`.<br>
You can include the updated artifact in your module’s `build.gradle` file as shown below:

```groovy
implementation "com.adswizz:adswizz-sdk:7.12.0" // AdsWizz SDK module
// implementation "com.adswizz:exoplayer2-19:7.11.1" // Deprecated ExoPlayer-specific wrapper module
implementation "com.adswizz:exoplayer2x:7.12.0" // New unified ExoPlayer wrapper module
implementation "com.google.android.exoplayer:exoplayer:$YourExoPlayerVersion" // Specify your desired ExoPlayer 2.x version here 
```
> **Note**
> The "com.google.android.exoplayer:$YourExoPlayerVersion" dependency must be present in your `build.gradle` in order to successfully use the `com.adswizz:exoplayer2x` wrapper.

### Integrating with `Android Media3`

The `com.adswizz:exoplayer-media3` artifact (used by the **_AdswizzSDK_**'s’s InternalPlayer) is now compatible with `androidx.media3:media3-exoplayer` up to version 1.5.1. Starting with this 7.12.0 release, **_AdswizzSDK_** no longer includes `androidx.media3:media3-exoplayer` as a transitive dependency.
You’ll need to explicitly declare the required Media3 dependencies in your module’s `build.gradle` file, as shown below:

```groovy
implementation "com.adswizz:adswizz-sdk:7.12.0" // AdsWizz SDK module
implementation "com.adswizz:exoplayer-media3:7.12.0" // AdsWizz wrapper for Media3 integration

// Add required Media3 dependencies (specify your Media3 version)
implementation "androidx.media3:media3-exoplayer:$YourMedia3Version"
implementation "androidx.media3:media3-exoplayer-dash:$YourMedia3Version"
implementation "androidx.media3:media3-exoplayer-hls:$YourMedia3Version"
implementation "androidx.media3:media3-exoplayer-smoothstreaming:$YourMedia3Version"
```
> **Note**
> The following dependencies: "com.google.android.exoplayer:exoplayer", "androidx.media3:media3-exoplayer-dash", "androidx.media3:media3-exoplayer-hls", "androidx.media3:media3-exoplayer-smoothstreaming" must be present in your `build.gradle` in order to successfully use the `com.adswizz:exoplayer-media3` wrapper.
